# 使用与许可边界

## 当前事实

1. 上游仓库 `MengTo/kage` 是公开仓库，并开放 GitHub fork 功能。
2. 上游 README 明确声明：原始 Kage 代码和美术目前**没有授予复用或再分发许可**。
3. 仓库中的 vendored Three.js r149 保留自己的 MIT 许可声明；这不会自动覆盖 Kage 的其余代码和美术。
4. GitHub 官方说明：公开仓库可以被查看和 fork；但没有许可证时，默认著作权规则仍然适用，不能据此推导出复制、分发或创作衍生作品的通用授权。

## 这份 fork 可以做什么

- 通过 GitHub fork 功能保存上游历史与来源关系；
- 学习、审阅和讨论其实现；
- 保存独立撰写的研究笔记和行为规格；
- 为未来独立重写制定模块、测试和美术资产合同；
- 向上游作者申请单独的书面商用授权。

## 在获得授权前不要做什么

- 把原始代码或素材复制进客户网站；
- 把这个 fork 宣传为“可商用模板”或“开源标准库”；
- 给整个 fork 添加一个宽松 LICENSE，并声称它覆盖上游内容；
- 更换品牌后继续使用同一套场景图、透明素材、文案或源代码表达；
- 删除上游来源、作者信息和第三方许可声明。

## 客户项目的两条安全路线

### 路线 A：取得授权

向权利人说明使用范围、客户数量、托管方式、是否允许修改、是否允许再分发和署名方式，取得书面许可后再实施。

### 路线 B：独立重写

只把本研究中的抽象行为和工程约束作为需求，重新设计代码结构、API、shader、几何、镜头、文案、品牌和所有美术资产，并保留能证明独立创作过程的设计稿、提交记录和资产来源。
