# Kage 深度拆解：它为什么不像网页，而像一个可以行走的镜头

## 结论先说

Kage 不是“把一个三维场景塞进 HTML”，也不是普通网页加若干视差动画。它真正做的是：**用滚动控制一台虚拟摄影机，让 Three.js 世界、HTML 编辑排版、透明前景素材、独立卡片画布和后期调色共同服从同一个镜头叙事。**

它的高级感不是来自某个昂贵模型。寺院、台阶、鸟居、灯笼、地形等主体其实都是运行时程序化搭建的简化几何。真正昂贵的是系统性：空间层次、素材色调、镜头位置、遮挡关系、动画时间、字体、交互反馈和性能降级全部朝同一个艺术方向工作。

## 一、画面到底分了多少层

肉眼看到的“前后画面”至少由七层共同组成，而且不只靠 CSS `z-index`：

| 层级 | 技术 | 画面职责 |
|---|---|---|
| 1. 三维远景 | Three.js 世界坐标 | 天空、山体、月亮、雾，给出纵深和气候 |
| 2. 三维主体 | Three.js 几何与灯光 | 寺院、鸟居、台阶、灯笼、水面，形成可移动摄影机的真实空间 |
| 3. 三维近景 | 多张带透明通道的程序化平面 | 草、岩石、树枝贴近镜头，遮挡建筑与巨型字标，制造“镜头在植物之间穿行”的感觉 |
| 4. 三维动态介质 | 粒子、实例化网格、Shader | 雨、雾、余烬、落叶、水波、鼠标冷色微粒，让空气本身可见 |
| 5. HTML 编辑层 | 标题、正文、章节、导航、卡片 | 提供真正可读、可响应式布局的内容，不把文字烘焙进三维画面 |
| 6. HTML 超近景 | 透明 WebP 前景素材 | 每章独有的樱花、枫叶、石灯、墙体、灌木等，能压到正文和导航前面 |
| 7. 镜头后期 | bloom、grain、vignette、色调编码 | 把来源不同的 3D、图片和 DOM 统一成同一种“夜间胶片” |

最聪明的是第 6 层。每章的透明前景原本属于自己的 section；章节成为当前镜头时，整组前景会被临时搬到页面外部的固定容器 `#fg-sky`。这个容器位于 `.page` 的堆叠上下文之外，因此枝叶真的能够从正文前面穿过，甚至压过固定导航和右侧章节轨道。

章节交接不是切换开关。新章前景上升进入，旧章前景仍保留约 820ms，期间下沉约 `8vh`、缩小到 `.98`、模糊到 `18px` 并淡出，随后才搬回原章节。实测过渡阶段 DOM 中同时存在一个 `fg-active` 和一个 `fg-retiring`。所以人眼感受到的是景深焦点交接，不是图片轮播。

## 二、鼠标为什么显得“有生命”

一次鼠标移动会同时进入四条反馈通道：

1. **光标本身**：自定义圆环不是紧贴系统指针，而是每帧以 0.18 的比例追赶目标位置，形成轻微黏滞感；进入可交互区域时从 26px 扩到 52px。
2. **摄影机视差**：指针换算成 `[-1, 1]` 范围，经过与帧率无关的阻尼后，轻推摄影机位置，同时反向微调观看目标。背景和近景因此产生真实空间视差，而不是整张图一起位移。
3. **鼠标微粒**：冷色光点挂在摄影机坐标系里，按照鼠标走过的距离而不是时间发射；慢移形成连续漂流，快甩则拉开粒子间距。发射源自己还会稍微落后于鼠标，所以不是一条机械点阵。
4. **世界状态**：章节编号或课程项悬停时，`RIG.focus` 被激活。灯笼亮度最高可增加约 55%，大殿灯光和月晕同步增强。也就是说，悬停不是一个 DOM 元素自己的事情，整个寺院都会回应。

这就是它与一般“按钮变色”网页的本质区别：局部操作被翻译成了镜头、空气和照明的变化。

## 三、卡片为什么不像普通图片

浏览器里一共能看到四个 canvas：一个主场景，加三张卡片各自的 WebGL2 canvas。

每张卡片会把原始场景图和上下两道暗部渐变先烘焙为一张 plate，再覆盖到一个 `97 × 97` 节点的网格上，共 9,409 个模拟点。程序用有限差分波动模拟计算网格高度，包含：

- 顶边固定；
- 风力、阵风、阻尼和垂坠；
- 鼠标位置的弹簧平滑；
- 鼠标压痕与波纹传播；
- 折痕明暗、布面 sheen、边缘高光、接触阴影和圆角。

因此鼠标进入卡片时，不只是卡片上浮或图片缩放，而是**画面、暗角、边框和阴影作为一块布一起变形**。边框必须在 shader 中重绘，否则普通 CSS 边框会留在平面上，立刻暴露这是叠加特效。

与此同时，代码还为卡片准备了独立的 Three.js 摄影机视角。未启用织物覆盖的路径中，卡片可以成为通向同一个寺院世界的“活窗口”，悬停时摄影机会向观察目标轻推。为节省性能，每个视口只有在移动或轮到刷新时才重新渲染，并会剔除屏外、透明或已由织物接管的卡片。

卡片内的月亮和灯笼也不是同一种循环动画：月亮慢速呼吸，灯笼用手工写出的不规则明灭节奏。两条互不整除的周期叠加，使循环不容易被识破。这类差别很小，却决定画面是“生物感”还是“屏保感”。

## 四、滚动不是把页面往上推，而是在剪辑镜头

场景定义了六个摄影机 waypoint：首屏、山门、庭园、手艺、余光、页脚。每个点都保存位置、观察目标和 FOV，再分别接成 Catmull–Rom 曲线。

滚动位置先映射到章节间的分数进度，再通过阻尼跟随。摄影机位置、观看目标和视角沿曲线连续插值，因此章节不是六个场景，而是同一个空间的六个构图。

首屏还有独立的长焦推进：开场时摄影机更远、略高、FOV 更大，约 2.4 秒内缓慢落入正式机位。竖屏下则沿视线后退并扩大 FOV，避免照搬桌面机位后把鸟居和建筑两侧裁掉。

首屏离场也被当作剪辑处理：预览窗先快速模糊溶解，滚动提示随后下移淡出，四个章节编号按次序撤场，最后才收走章节行和日文侧标。整个过程只占首个约 0.58 个视口的滚动，不使用普通 0.9 秒 transition，以免动画滞后于手指。

## 五、所有小按钮都遵守同一种动作语法

它没有给每个按钮随便发明一种夸张特效，而是反复使用几种统一语法：

- **翻译而非弹跳**：导航英文向上退出，日文从下方进入；编号只上移 2px。
- **线条生长**：课程底线、章节轨道、导航状态线从细线长度变化建立方向感。
- **底色推进**：CTA 的骨白色填充从下往上滑入，文字和箭头变为深色。
- **方向性箭头**：圆形链接填充后，箭头向右上移动 2px；卡片箭头从左下微移到原位。
- **低幅度、长缓动**：常用 0.45–0.7 秒和自定义 `ease-out`，没有弹簧抖动，也没有无意义大缩放。

标题进入则按词处理：每个词由遮罩下方升起，词间约 72ms；普通内容组按约 85ms 错开。前景素材的入场延迟是 0/90/180/270ms。多套节奏接近但不完全相同，所以整页有统一呼吸，却不显机械。

## 六、美术为什么统一

### 色彩结构

它把绝大多数区域限制在近黑、蓝炭、灰绿和骨白，暖色只留给三类叙事对象：朱红月亮、灯笼/障子光、交互状态。冷暖不是装饰，而是告诉眼睛“什么是空气、什么是生命、什么可以操作”。

### 字体与留白

英文标题不是铺满中央，而是像杂志跨页一样偏置；日文竖排承担右侧视觉重量；极小的章节标签、细规则线和大块负空间建立档案/展览气质。桌面默认启用的 B 版布局甚至为六个章节分别设计了不同版式：首屏分栏、故事跨页、庭园马赛克、课程图谱、竖排收束、宣言式页脚。它不是一个通用 section 模板重复六次。

### 图片不是背景库存

四张场景 plate 分别采用横、竖构图，透明前景则保留 alpha 并按章节重新取景。主场景负责连续空间，图片负责瞬间的电影质感，透明素材负责超近景遮挡。颗粒、暗角、统一饱和度和亮度过滤把三种来源焊成一个视觉世界。

## 七、后期合成为什么重要

主场景先渲染到半浮点 render target，再做亮部提取。亮部依次经过四层降采样和横/纵模糊，之后从最小层向上叠加，形成宽窄不同的 bloom，而不是给所有东西统一发光。

最终合成再加入：

- 冷阴影与暖高光的色调分离；
- 轻微 vignette；
- 程序噪点；
- gamma 编码；
- 低枢轴对比度修正；
- 开场淡入。

它让障子、灯笼、月亮和微粒发光，却尽量保住屋檐黑色剪影。若把 bloom 强度简单拉高，整座寺院会变成发亮的纸模型，深度立刻消失。

## 八、它不是只顾效果，也认真控制了代价

- 项目有效载荷约 **3.63 MB**：WebP 约 2.67 MB，Three.js 约 0.61 MB，单页 HTML 约 0.25 MB。
- 没有 npm、构建步骤、环境变量、分析脚本或运行时网络请求；普通静态服务器即可。
- 运行中统计真实帧耗时；变慢时先降低 render scale，最低约 0.55，并优先关闭多重采样。
- 低质量模式减少雾、余烬、雨、水波、落叶和鼠标微粒数量，并降低阴影贴图。
- 触屏/粗指针设备不创建自定义光标、鼠标微粒和卡片织物模拟。
- `prefers-reduced-motion` 会取消持续动画、转场和逐词揭示，但保留所有内容。
- 页面不可见时暂停主渲染循环，卡片织物也用 IntersectionObserver 停止屏外更新。
- WebGL 启动失败时切换为 CSS 静态背景和 DOM 字标，而不是让页面变空。

## 九、真正值得借鉴的地方，以及它的弱点

值得借鉴的不是“黑底、红月、日文字”，而是下面四条工程方法：

1. 先定义镜头和叙事，再决定每个技术层做什么。
2. 同一输入同时影响局部 UI 与全局世界，形成因果感。
3. 让素材、边框、阴影一起变形或一起调色，避免叠加层穿帮。
4. 所有重效果都配有移动端、低性能、减少动画和 WebGL 失败路径。

它也有明确代价：

- 约 4,800 行 HTML/CSS/JS 全在一个文件里，作品便携，但长期维护和多人协作困难。
- Three.js r149 较旧；未来升级会触及颜色管理、render target 和 shader 兼容。
- 主画布加三张卡片意味着四个 WebGL 上下文，虽然有剔除和暂停，低端机器仍然需要严格测试。
- 内容高度或章节结构一旦大改，摄影机 anchor 和构图也要重新调，不是换文案即可复用。
- 卡片视觉上像可点击对象，但当前主要承担体验展示；若用于真实产品，需要补足键盘焦点、链接目的和操作语义。
- 视觉原创素材和 Kage 源码没有授予复用/再分发许可证，不能把现成仓库直接当作可商用模板发布。

## 十、能不能做出“一模一样的感觉”

**技术上能，而且我们已经掌握了关键机制。** 但应区分两种“一模一样”：

- 原样复制 Kage：现有源码当然能运行，但许可证明确不允许复用或再分发原始代码与美术。
- 做出同等级、同机制、同完成度的新作品：完全可行。应重新写实现、重新生成/绘制素材、重做品牌与内容，同时保留它最有价值的系统结构。

一个合法的高保真实现应拆成六个工作包：

1. **品牌与镜头脚本**：题材、色盘、字体、六个章节和每章镜头目的。
2. **原创美术资产**：四至六张场景 plate，约十张透明前景，统一颗粒、色温、透视和光源。
3. **三维世界**：程序化建筑、地形、灯光、水面、雾雨落叶与镜头曲线。
4. **编辑排版层**：每章独立构图、前景接管、首屏撤场、响应式版式。
5. **交互层**：黏滞光标、镜头视差、世界 focus、微粒轨迹、织物卡片与微动效语法。
6. **后期与验证**：bloom/调色、性能预算、移动端、减少动画、WebGL fallback、完整滚动和控制台检查。

若只复刻黑红配色和视差，大约只能得到它 30% 的感觉。要达到同等级，最不能省的是：**原创素材的统一 art direction、章节级镜头构图、前景交接、局部交互对全局世界的联动、以及性能降级。**
